# LLM Wiki

Годовой проект по теме:

**LLM Wiki: desktop-сервис для автоматического построения персональной базы знаний с помощью LLM, Knowledge Graph и Deep Research**

## Команда

**Студент:** Закусов Кирилл Ярославович  
**Куратор:** Мустафин Фарид

## Описание проекта

Цель проекта — разработать локальное приложение для построения персональной базы знаний на основе пользовательских документов, статей и веб-страниц.

Система должна автоматически обрабатывать добавленные материалы, извлекать из них информацию и формировать взаимосвязанные wiki-страницы. Пользователь сможет искать информацию по накопленной базе знаний и задавать вопросы LLM с получением ответов со ссылками на исходные материалы.

В дальнейшем предполагается исследовать возможность использования Knowledge Graph, graph-aware retrieval и Deep Research для улучшения навигации и поиска информации.

## Предполагаемый MVP

В базовую версию планируется включить:

- импорт документов и веб-страниц;
- обработку и разбиение документов на фрагменты;
- хранение исходных материалов и метаданных;
- vector search;
- keyword search;
- автоматическую генерацию wiki-страниц;
- связи между сгенерированными страницами;
- RAG-чат по пользовательской базе знаний;
- цитирование исходных материалов в ответах;
- инкрементальное добавление новых документов;
- локальное desktop-приложение.

## Дополнительные направления

После реализации основной версии могут быть рассмотрены:

- Knowledge Graph;
- graph-aware retrieval;
- автоматическое определение пробелов и противоречий в базе знаний;
- Deep Research Agent;
- поддержка мультимодальных документов;
- локальный запуск open-weight LLM;
- MCP/API для подключения базы знаний к другим AI-системам;
- сравнение Classic RAG, Persistent Wiki и Graph-enhanced RAG/Wiki.

Конкретный набор дополнительных возможностей будет определяться по мере работы над проектом.

## Предварительный план работы

### Этап 1. Постановка задачи и проектирование

- уточнение требований и scope проекта;
- исследование существующих подходов;
- проектирование архитектуры приложения;
- определение форматов хранения документов, wiki-страниц и индексов;
- выбор основных технологий.

### Этап 2. Ingestion и поиск

- импорт документов;
- парсинг и нормализация данных;
- chunking;
- построение embedding-индекса;
- реализация vector search;
- реализация keyword search;
- объединение методов поиска.

### Этап 3. Wiki

- автоматическая генерация wiki-страниц;
- выделение основных сущностей и концептов;
- построение связей между страницами;
- хранение связи wiki-страниц с исходными документами;
- инкрементальное обновление wiki при добавлении новых материалов.

### Этап 4. RAG

- реализация retrieval pipeline;
- интеграция LLM;
- чат по базе знаний;
- генерация ответов с цитированием источников;
- оценка качества retrieval и ответов.

### Этап 5. Desktop-приложение

- интерфейс загрузки и управления документами;
- просмотр wiki;
- поиск;
- чат;
- просмотр источников и связей между материалами.

### Этап 6. Экспериментальная часть

Предполагается сравнить несколько подходов к организации персональной базы знаний:

- Classic RAG;
- Persistent Wiki;
- Graph-enhanced Wiki/RAG.

Будут выбраны набор сценариев и метрики для сравнения качества поиска и ответов.

### Этап 7. Дополнительные возможности

В зависимости от результатов предыдущих этапов и доступного времени:

- Knowledge Graph;
- graph-aware retrieval;
- knowledge gaps;
- Deep Research;
- MCP/API;
- локальные LLM.

### Этап 8. Завершение проекта

- тестирование;
- исправление ошибок;
- проведение итоговых экспериментов;
- подготовка документации;
- подготовка демонстрации и результатов проекта.
